# ELX suite 0.1.1 — power indicators

ELXbat 0.1.3 and ELXdash 0.1.1 now show automatic power-source indicators:

- A plug with a short cable for external power; a battery outline for battery power.
- A lightning bolt only when firmware reports active charging, including fast charging.
- A question mark and unknown/stale message after a read failure, with automatic recovery.
- One-second read-only firmware-status polling and partial redraws when that status changes.
  Gauges retain their existing five-second default refresh.

ELXbat retains its last complete battery snapshot on a failed refresh, marks it
stale and retries. Neither utility changes charging or power settings as part
of monitoring. The README now includes credits and inspiration.

| ELXdash | 0.1.1 |

Download **ELX-Suite-0.1.1-binaries.zip** for all six ELKS executables, or
**ELX-Dashboard-Pack-0.1.1.zip** for the two updated tools, sibling source,
previews and build/test evidence. Source archives match `SOURCE-COMMIT.txt`.
`SHA256SUMS` verifies downloads; `BINARY-MANIFEST.json` identifies each executable.

Validation: host tests with address/undefined-behaviour sanitizers; 8086
cross-builds and instruction/memory audits; native elksemu CLI, model and
framebuffer tests; production ELXbat loop exercised with fake clock, console
and firmware reads. Tests cover charging vs enabled/inactive, unplugging,
read failures/recovery and unchanged pixels outside the power strip.

**Physical HP plug/unplug timing remains unverified.** The firmware controls
when its cached status changes; polling once a second does not guarantee
one-second detection. Previews use synthetic/offline data, not physical hardware.
No kernel, CF image, startup configuration or charging policy is changed.
